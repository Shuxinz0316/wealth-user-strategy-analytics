# 面试讲解指南

## 90 秒版本

我做了一个互联网财富平台的新用户转化和沉睡召回项目。数据是我按真实业务逻辑生成的 12,000 名模拟用户，包含行为、交易、产品和实验六张表。我先用 SQL 构建生命周期、渠道漏斗、cohort 留存和资产分层，发现最大断点是注册到开户，开户率只有 31%；同时识别出 2,351 名高现金未投资用户。

针对沉睡用户，我设计了对照、教育内容、产品推荐三组随机实验，用 ITT 分析。产品推荐把 30 日购买率从 3.6% 提到 7.0%，教育内容提到 6.6% 且留存更高。异质性显示，谨慎型用户更适合教育内容，平衡和进取型更适合风险匹配的产品推荐，所以我的最终建议是分层路由，而不是全量推同一内容。

我还用 DID 评估区域灰度活动，并用逻辑回归做流失名单排序。整个项目从模拟数据、SQLite、SQL、统计检验到图表和策略报告都可以一键复现。对我来说重点不是模型复杂，而是把发现转成动作，再用实验验证真正的增量效果。

## 5 分钟展开顺序

1. 业务问题：短期购买不是唯一目标，长期留存 AUM 和适当性是北极星。
2. 数据建模：六张表、用户粒度去重、指标口径与质量检查。
3. 诊断：开户是主要断点；渠道质量不能只看注册成本。
4. 分层：现金、AUM、频次、最近购买、风险偏好共同决定动作。
5. 实验：分层随机、ITT、MDE、置信区间、护栏、异质性。
6. 落地：谨慎型教育，平衡/进取型合规推荐，长期 holdout。
7. 局限：数据为模拟；真实上线要补投诉、赎回、行情和费率。

## 常见追问

### 为什么不用点击率作为核心指标？

点击离业务价值太远，而且标题党可能提高点击却损害信任。购买率更接近结果，但仍需留存、赎回和投诉做护栏，最终看长期留存 AUM。

### 为什么按 ITT 而不是只分析送达用户？

是否送达可能与设备、活跃和用户质量相关。剔除未送达人会破坏随机化。ITT 回答“把用户分配到该策略”带来的真实运营效果。

### 两个处理组哪个更好？

两组分别相对对照显著，不代表二者差异显著。点估计显示产品推荐购买更高、教育内容留存更好。我会预注册下一轮分层路由实验，直接比较长期价值。

### DID 的关键假设是什么？

如果没有活动，试点组和对照组应有平行趋势。图形只能提供初步证据，还需事件研究、安慰剂、同期政策排查和稳健标准误。

### AUC 0.658 是否太低？

它是可解释基线，不应包装成高精度模型。它对名单排序有一定价值，但是否值得触达必须用增量实验验证。下一步会比较梯度提升，同时优先补充触达历史、行情敏感度和产品持仓特征。

### 如何避免金融推荐伤害用户？

先校验营销授权、风险测评有效期和产品风险等级；展示风险、费用和流动性，不承诺收益；设置频控和退出机制；同时监控投诉、短期赎回和弱势用户指标。
